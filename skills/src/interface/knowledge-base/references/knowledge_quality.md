# Knowledge Quality Criteria

Use this for review of MKF concepts, bundles, or knowledge-interface consumers.

## Review Questions

1. Is the concept focused on one durable idea or reusable artifact?
2. When present, are title and description clear and specific?
3. When present, do tags improve retrieval without becoming noisy?
4. Are citations or keyed source footnotes present where claims need attribution?
5. Are indexes clearly separate from authored concepts and useful for progressive disclosure?
6. Can manual bundle discovery be understood from visible environment/path information?
7. Are lookup/search behaviors kept out of passive knowledge contract material?
8. Are write/update/index-rebuild behaviors kept in record tooling?
9. When advanced OKF fields are present, do provenance, trust, lifecycle, and attestation metadata support an informed consumer judgment?

## Common Findings

- Concept mixes unrelated ideas.
- Optional description is too vague to help lookup results.
- Tags duplicate title words without improving retrieval.
- Operational behavior leaks into the interface contract.
- Reserved index or log files are treated as concepts.
- Advanced metadata is asserted without source or lifecycle context.
