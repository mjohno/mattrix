# Retro Checklist

Use this for conformance checks. A retro passes when every Critical item passes.

## Critical

- [ ] Has a title plus `Session`, `Goal`, and `Evidence` fields.
- [ ] Has `Wins`, `Issues`, and `Actions` sections.
- [ ] Every win describes an observable helpful result and its value.
- [ ] Every issue states evidence, effect, and known contributing conditions; unknown conditions are labeled.
- [ ] Issues do not assign personal blame.
- [ ] Actions contain one to three bounded improvements.
- [ ] Each action is a concise INVEST task statement, checked with the `task` skill's Quality Checklist, or is explicitly incomplete because required context is missing.
- [ ] Actions do not include an assignee, due date, follow-up date, or tracking reference.
- [ ] Unsupported claims, completion statements, and invented evidence are absent.

## Quality

A failed Quality item produces a `Partial` result. It does not fail conformance.

- [ ] The session boundary and goal make the retro understandable without full session context.
- [ ] Wins identify practices or conditions worth repeating.
- [ ] Issues focus on systems, processes, tools, or context rather than people.
- [ ] Evidence separates observed facts from likely contributing conditions.
- [ ] Actions address the most valuable issues rather than every observation.
- [ ] Actions state a useful outcome without prematurely fixing the implementation.
- [ ] The retro is concise enough to read and maintain.
