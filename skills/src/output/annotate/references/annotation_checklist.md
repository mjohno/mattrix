# Annotation Checklist

Use this checklist before returning an annotation change.

## Structure

- [ ] The annotation uses a supported kind: NOTE, TODO, FIX, CHECK, REVIEW, or DONE.
- [ ] It has a stable, relevant ID and uses the target file's native comment syntax.
- [ ] Its message is concise, actionable when applicable, and near the relevant code or prose.
- [ ] References are included when they link to source material.

## Change Scope

- [ ] The targeted annotation was identified by ID, text, or local context.
- [ ] Only the requested annotation changed; unrelated content and formatting remain intact.
- [ ] Updates preserve the ID when the same annotation changes purpose or status.
- [ ] DONE marks completion without claiming work that has not occurred.
